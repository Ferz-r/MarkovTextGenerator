# Markov API

FastAPI-обёртка для генерации текста марковской цепью.

## Запуск

```sh
uv sync
uv run python main.py
# или с автоматической перезагрузкой
uv run uvicorn main:app --reload
```

API: http://127.0.0.1:8000/api/v1. Swagger: http://127.0.0.1:8000/docs.


При запуске приложение загружает `data/model.pkl.gz`: токенизатор, словарь,
компактный индекс переходов и настройки. Обучение и загрузка источников при этом
не выполняются. Если файл отсутствует, повреждён или несовместим, корпус загружается
и модель обучается один раз. Старый `data/texts.json` читается только для первого
обучения при миграции; новый кеш исходных текстов больше не записывается.

После дообучения, замены корпуса или изменения настроек модель автоматически
сохраняется атомарно: временный файл заменяет предыдущий только после полной записи.
Параметры сохранённой модели имеют приоритет над значениями старта сервиса.
Тексты входят в снимок модели для дальнейшего переобучения и работы с темами.
Без них нельзя переключить токенизатор или пересчитать новый контекст на прежних данных.
Модель использует версионированный gzip-снимок примитивных данных; загрузчик запрещает
десериализацию Python-классов. Используйте один worker: каждый worker имеет свою модель.

## Методы

- `GET /api/v1/health` — готовность приложения.
- `GET /api/v1/model` — число текстов, размер словаря и число контекстов.
- `POST /api/v1/generate` — генерация по `prefix` и необязательной теме `topic`.
- `POST /api/v1/train` — дообучение по списку `texts`; `replace: true` заменяет корпус.

```sh
curl -X POST http://127.0.0.1:8000/api/v1/generate \
  -H 'Content-Type: application/json' \
  -d '{"prefix": "Однажды", "topic": "Москва"}'

curl -X POST http://127.0.0.1:8000/api/v1/train \
  -H 'Content-Type: application/json' \
  -d '{"texts": ["Новый текст для обучения."], "replace": false}'
```

Неизвестная или пустая тема и некорректные входные данные возвращают HTTP 422.
Дообучение пересчитывает словарь и переходы всего текущего корпуса.
Генерация и обучение синхронизированы, выполняются в пуле потоков.
Изменения через `/train` сохраняются в файле обученной модели.

Логи используют формат Uvicorn (`INFO:`, `WARNING:`, `ERROR:`). В терминал выводятся
этапы обучения с прогрессом примерно каждые 10% и прошедшим временем.

## Структура

- `main.py` — создание приложения, lifespan и запуск сервера.
- `src/markov/api/` — маршруты и схемы запросов/ответов.
- `src/markov/service.py` — общий экземпляр модели и синхронизация операций.
- `src/markov/corpus.py` — загрузка источников и чтение старого кеша для миграции.
- `src/markov/logging.py` — настройка логов и прогресс обучения.
- `src/markov/markov_chain.py`, `rules.py`, `tokenizer.py` — алгоритм и токенизаторы.

Проверки: `uv run python -m unittest discover -s tests`.
Для тестов нужен `httpx`: `uv sync --group dev`.

Настройки модели доступны в интерфейсе и через `POST /api/v1/settings`:
`{"n_gramm": 3, "min_frequency": 5, "max_length": 100}`.
Текущие значения возвращает `GET /api/v1/model` в поле `settings`.
Контекст (1–50) и частота (1–100000) пересчитывают модель на текущем корпусе.
Длина (1–10000 новых токенов) применяется без обучения. Настройки сохраняются между запусками и общие для всех пользователей. Значения старта задаются в `backend/main.py`.

При обучении и пересчёте интерфейс показывает прогресс текущего этапа, число
обработанных элементов и время этапа. Процент начинается заново на каждом этапе.
`POST /api/v1/train/stream` и `/api/v1/settings/stream` возвращают SSE-события
`start`, `progress`, `complete` или `error`; обычные JSON-методы сохранены.
Прерывание соединения не отменяет уже запущенное обучение.

`POST /api/v1/train/file/stream` принимает multipart-поля `file` (.txt),
`replace` (bool) и необязательное `texts` (JSON-массив дополнительных текстов).
Бэкенд обучает модель на каждой непустой строке файла отдельно; временный файл
удаляется после обработки. SSE включает этап чтения файла и этапы обучения.

Для генерации по теме строится отдельная таблица по текстам, содержащим тему.
Она рассчитывается один раз и кешируется (две последние темы). При смене контекста
или частоты кешированные темы готовятся в рамках пересчёта настроек.
Дообучение или замена корпуса сбрасывают кеш; новая либо вытесненная тема требует
одного расчёта при первом запросе. Лог этапа: «Переходы для темы …».

## Компактный индекс переходов

`src/markov/transitions.py` хранит один упакованный целочисленный ключ на пару
полного контекста и следующего токена. Записи сортируются по обратному контексту;
для короткого контекста частоты точно суммируются по соответствующему диапазону
индекса. 50 отдельных таблиц и длинные кортежи больше не создаются при обучении.
Распределения коротких контекстов кешируются по запросу. Вероятности и число
контекстов сохранены; порядок токенов при случайном выборе может отличаться.

После подсчёта переходов отображается дополнительный этап индексирования.
`model.transitions` для совместимости разворачивает полную старую таблицу:
не вызывайте это свойство для большого корпуса ради статистики, используйте
`model.contexts_count` или `/api/v1/model`.

Сравнение на первых 20 000 символах локального корпуса, CharacterTokenizer,
min_frequency=3, ngramm=50 (каждый вариант в отдельном процессе):

| Подсчёт | Время | Контекстов | Пиковая память всего процесса |
| --- | --- | --- | --- |
| Прежний | 0,639 с | 896 237 | 684,5 МБ |
| Индекс | 0,009 с | 896 237 | 188,3 МБ |

Память включает загрузку исходного JSON-корпуса и интерпретатор. Это небольшая
проба, не замер полной книги; ускорение зависит от корпуса и длины контекста.
Повторить сравнение: `uv run python benchmarks/transitions.py`.

Выбор токенизатора: `settings.tokenizer` принимает `character` (по символам,
по умолчанию) или `regex` (слова, числа, пробелы и пунктуация). Настройка доступна
в UI и в обоих методах `/api/v1/settings` и `/api/v1/settings/stream`. Смена
токенизатора пересчитывает словарь, переходы и кешированные темы на текущем
корпусе. Частота и длина контекста/генерации измеряются в токенах выбранного типа.
Для выбора при старте в `backend/main.py`: `MarkovService(tokenizer_type="regex")`.

Снимки модели: `src/markov/storage.py`. Для тестового приложения сохранение выключено
по умолчанию; включается через `create_app(..., model_path=Path(...))`.
